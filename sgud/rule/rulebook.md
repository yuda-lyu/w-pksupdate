# 規則帳本

本檔為套件設計與開發階段之規則帳本,為要求程式碼須長成什麼樣,或由規格產出之測試(項目/說明/流程)有哪些,包含軸、單一擁有者、已知限制、破壞性變更紀錄,以及對應是哪些測試檔案或指令等,由agent自行編列、擴充與維護.

- **R27 registry 不得寫死,一律經解析模組**:全套件之安裝依賴、確認新版已上架、發布(含同時發布之鏡像)所用之倉庫位址,一律來自 `src/registryConfig.mjs` 之 `resolveRegistryConfig`(單一擁有者);程式碼(去註解後)不得出現任何倉庫位址字面值(含 npmjs).`g_updateAndPublic.mjs` 之註解範例不算(註解).
- **R27.1 倉庫設定**:`resolveRegistryConfig(opt)` 回傳 `{ main, mirrors, source, notes }`.
  - **主倉庫**(安裝依賴、發布、確認上架皆用它)優先序:選項 `registry`(`g_updateAndPublic.mjs` 之 `optRegistry`)> 環境變數 `W_PKSUPDATE_REGISTRY` > `npm config get registry`(本機 npm 設定).**解析失敗明確 throw `[registry] …`,不默默退回 npmjs**;選項或環境變數給了無效位址同樣 throw,不改道.
  - **鏡像倉庫**(同時發布之對象):選項 `mirrors`(字串或陣列;給了即採用,空陣列 = 明確無鏡像)> 環境變數 `W_PKSUPDATE_MIRRORS`(逗號、分號或空白分隔)> 無(預設).可多個,去重,與主倉庫相同者略過並留提示.
  - **只解析一次**:`publishPackages` 於迴圈前解析、印一行 `[registry] 主倉庫: …(來源: …); 同時發布之鏡像: …`,以 `opt.registryConfig` 往下傳(`publishPackage` → `runScript` / `ectScripts`);`publishPackage` 缺 `registryConfig.main` 即於任何副作用之前 throw `[registry]`,`checkNpmVersion` 缺 `opt.registry` 即 throw,皆不退回預設倉庫.
- **R27.2 位址正規化與拒收**:`normalizeRegistryUrl`(冪等)——只收 `http(s)://`,主機轉小寫、預設埠移除、結尾補 `/`;拒收非 http(s)、含使用者資訊(帳密)、查詢字串、片段、IPv6 字面位址,以及輸入原文與標準化結果含 `[A-Za-z0-9._~:/%+-]` 以外字元者(位址會被組進交給 PowerShell 之指令列;**逗號不容許**——PowerShell 未加引號之逗號為陣列運算子,且與鏡像清單分隔符衝突;只驗標準化結果不夠,URL 解析器會把空白、引號悄悄改寫成 `%20`、`%22`).被拒位址若引述於錯誤訊息,`//` 至其後第一個 `/` 之間含 `@` 者整段遮蔽(帳密可含空白與多個 `@`)、截至 80 字元.**選項型別**:`registry` 非字串、`mirrors` 非字串或字串陣列(含非字串元素)一律 throw(不當成未設定而改道,也不悄悄關閉鏡像);空字串視為未設定;`mirrors` 陣列的每個元素是一個完整位址(不切分),只有字串/環境變數形式才以逗號、分號、空白切分.
  - **安裝依賴**:`npm i --registry=<主倉庫>`(固定指定,沿用原『避免走到有延遲之鏡像或 CDN』之意圖).
  - **子行程 npm 以主倉庫為準**:`runScript` 對每個 `exec`(node、bin、git、npm 列)帶 `registry` 選項,`ectScripts` 之 `composeCommand` 於 `Set-Location` 之後設 `$env:npm_config_registry = '<主倉庫>'`(只作用於該 PowerShell 行程).npm 設定優先序為命令列旗標 > 環境變數 > 專案 `.npmrc` > 使用者 `.npmrc`,故不受執行機使用者設定與套件層 `.npmrc` 影響(`unit-ectScripts-ps` 以真 PowerShell + 真 npm 驗證含專案 `.npmrc` 指向別處之案).
- **R27.3 確認上架**:`checkNpmVersion(name, version, { registry })` 查主倉庫 `<主倉庫><name>/<version>?t=`、`<主倉庫><name>?t=`(`accept: application/vnd.npm.install-v1+json`)、metadata 的 `dist.tarball` 及其 HEAD;沿用原逾時、重試、快取避開參數(Verdaccio 兩端點皆支援,已對主控之倉庫實測).**鏡像不列入等待條件**.守望字樣 `npm上找不到` 不變(實際查的是主倉庫).**認證類錯誤快速失敗**:本函式的請求不帶 npm 認證(只適用允許匿名讀取的倉庫,主控的 Verdaccio 已實測可匿名讀);metadata、versions list、tarball HEAD 任一步連續回 401/403 達 `AUTH_FAIL_MAX`(20 次,約 1 分鐘)即停止等待並回 false(印診斷與停止行),不空等 2~3 小時;中間夾雜其他結果則計數歸零.限制:`dist.tarball` 的主機若與主倉庫不同(例如 CDN 或反向代理改寫),HEAD 打的是該主機.
- **R27.4 同時發布(鏡像)**:`runScript` 於主倉庫之 `npm publish` 列(script.txt 原列原樣執行)**成功後**,對每個鏡像依序再執行 `<原發布列> --registry=<鏡像>`(保留 `--tag` 等原參數;`src/mirrorPublish.mjs` 之 `publishToMirrors`).
  - **失敗只警告**:鏡像列失敗(含逾時〔單列 10 分鐘,`MIRROR_TIMEOUT_MS`;不用主列之 60 分鐘〕、spawn 失敗、認證失敗)不使該套件失敗、不中止連動,不重試;印 `[<套件>] 警告: 鏡像未同步(不影響本次連動), <套件>@<版本> → <鏡像>: <錯誤摘要>`,結果交 `opt.onMirrorResult` 彙整.主倉庫之 publish 失敗則已 throw,鏡像從未執行.
  - **已存在視為已同步**:鏡像回報 `cannot publish over [the] previously published version(s)`(npmjs 之 403)、`already present`/`E409`/`409 Conflict`(Verdaccio 之 409)→ `status=exists`;**單獨的 403(權限、停權)、`already exists`(可能是本機 EEXIST)不算**;**npm 另一則訊息 `Cannot implicitly apply the "latest" tag because previously published version X is higher…`(較高版本已存在)含 `previously published version` 但不表示本版已存在,不得判為已同步**(npm `lib/commands/publish.js` 第 180 行;評審 F11 查獲).
  - **列形與版本重驗**:鏡像列 = 原發布列 + `--registry=<鏡像>`;原列含獨立的 `--`(其後為位置參數)時,旗標插在 `--` 之前.主發布成功後讀一次版本(`vPub`)作為結果紀錄之版本,每個鏡像發布前除重過 `gateOutward` 外再重讀版本比對 `vPub`(版本閘門 R20.2 只在首個對外列前查一次,鏡像之間 npm lifecycle 可能改動 package.json),不符則該鏡像記為未同步而不發布.
  - **失敗摘要保留離開狀態**:`summarizeError` 取 `npm error` 行時,失敗標頭的 `code[N]`/`timeout[Nms]`/`spawn[…]` 冠於前;逾時後仍未落定(`仍未落定`)者標「狀態未知(子程序樹可能仍在執行,鏡像可能稍後才發布完成)」並置於前段不被截斷.
  - **結束摘要**:`publishPackages` 於結束(含中止)印 `[mirror] 摘要: 鏡像 …; 發布成功 N 筆、已存在視為已同步 M 筆、未同步 K 筆`,K>0 時逐筆列 `[mirror]   <套件>@<版本> → <鏡像>: <錯誤原文(截短 300 字、中和致命字樣)>` 並附補發方式(於該套件目錄執行 `npm publish --registry=<鏡像>`).錯誤文字經 `neutralizeFatal` 中和(內含 `npm指令失敗` 等守望字樣,不中和則守望器會把可容忍之鏡像失敗誤當連動中止).啟用鏡像時即使 0 筆也印首行.
  - **與閘門規則之整合(取捨)**:鏡像列是主發布列之延伸而非新的列類型——`classifyLine`/`isOutwardCmd`/`isRemoteCmd`/`loadScript` 不變,script.txt 不增列;主發布列已通過 `gateOutward`(版本 R20.2、建置主檔 R17.1)並已 `notifyRemote`(R21),**鏡像列不改變還原邊界**(`onRemote` 恰一次、早於主發布列);**每個鏡像發布前仍重過 `gateOutward`**,不通過則該鏡像記為未同步而不執行(不繞過閘門).取捨:閘門失敗時不 throw(主倉庫已發布,throw 會使套件在遠端已動之後中止,且鏡像本就容許失敗),而記為 `failed`.
- **R27.5 發布/安裝不得落到倉庫設定以外**(執行前檢查,守望字樣 `非預期指令`;皆在任何副作用之前):
  - script.txt 的 npm 列不得自帶倉庫旗標:`classifyLine` 以 `hasNpmRegistryOverride` 判定——去引號後逐記號比對 `--registry`、其唯一前綴縮寫(npm 的 nopt 接受 `--reg`、`--regi`…,至少 3 字元)、`--@scope:registry`(不分大小寫);命令列旗標優先於 `npm_config_registry`,會使發布/安裝落到設定以外之倉庫.
  - `loadScript` 另以 `getPublishTargetIssue` 拒絕:`package.json` 含 `publishConfig.registry`(npm publish 把 publishConfig 套到發布選項,優先於環境變數,僅命令列旗標更高;已對照本機 npm `lib/commands/publish.js` 實作)、套件名為 scoped(`@scope/name`,適用 `@scope:registry` 而壓過 `registry`).`package.json` 讀不到或無法剖析者不攔(交由其他閘門).全庫唯讀掃描(2026-10-28):121 個 script.txt 含 `registry` 者 0 個(發布列 119 列皆為 `#npm publish` 註解形);124 個 package.json 含 `publishConfig` 者 0 個.

### 2.4 已知限制

- **package-lock.json 會記錄 `resolved` 位址**:改以私有倉庫 `npm i` 後,lock 內來自私有倉庫之套件其 `resolved` 為私有倉庫之 tarball 位址(npm 的 `replace-registry-host` 預設只替換 npmjs 主機),隨 `git add -A` 進入公開 GitHub 庫——若私有倉庫為內網位址,將違反『公開庫不含內網位址』.本套件不處理(不改各套件之 lock),列為待主控裁示(見 pks-run01 修正報告).
- **鏡像發布各自重新打包**:每個鏡像列各自執行 `npm publish`,會各自觸發 `prepublishOnly`/`prepack` 並重新打包;若 lifecycle 產出不確定(時間戳、隨機值),各倉庫的同版本內容可能不同.全庫 124 個 package.json 的 `prepublishOnly`、`prepublish`、`prepack`、`postpack`、`prepare`、`publish`、`postpublish` 皆為 0(2026-10-28 唯讀掃描),故現為理論風險;日後出現此類 lifecycle 須改為重用同一 tarball.
- **發布列的其他形態不在支援範圍**:`npm --loglevel warn publish`(帶值全域選項)、`npm publ`(縮寫)、`npm publish --dry-run`、`npm publish ../其他套件` 等,既有的列辨識(`parseNpmCmd`,單一記號全域選項)與閘門都不涵蓋,屬舊有限制、非本輪引入;全庫 119 個發布列皆為 `#npm publish`(註解形,由 `parseScript` 改寫)。
- **既有 lockfile 的 `resolved` 若指向非 npmjs 之其他主機**,`npm i --registry=<主倉庫>` 仍會從該主機下載(`replace-registry-host` 預設只替換 npmjs 主機);`npm audit` 亦可能接觸 scope 專屬倉庫.本工具不檢查,安裝來源以主倉庫為準僅在 lockfile 與 scope 設定未另指他處時成立.
- **鏡像閘門失敗不中止連動**(設計取捨,評審曾建議改為中止):鏡像發布前閘門(版本、建置主檔)不通過時該鏡像不發布並列入摘要,連動繼續;主倉庫已發布成功、最終閘門仍查主倉庫.若認為此類情形(發布期間建置主檔或版本被動到)應中止整輪,改 `publishToMirrors` 對 gate 失敗重拋即可,現列待裁示.
- **鏡像子行程的即時輸出未經中和**:`ectScripts` 把子行程 stdout/stderr 原樣即時印出;致命字樣為本工具自己的中文訊息,npm 與 lifecycle 不會產生,故只中和我方訊息(失敗摘要、警告行),不處理子行程輸出.
- **`[registry] …` 錯誤不在 `FATAL_WORDS`**:解析失敗/位址無效以離開碼 1 結束且無 `>>> finish all`,「進程結束守望」可涵蓋;字樣守望器(§7.4 grep)不會命中.新增致命字樣須同步 `src/fatalWords.mjs`、`test/tools/fatalWords.mjs` 與 CLAUDE.md §7.4(本輪不得改 CLAUDE.md),列待主控裁示.
- **鏡像失敗無重試、無自動補發**:僅記入結束摘要,需人工依摘要補發.
- **CLAUDE.md §6.1 / §7.3 / §7.9 等多處文字以 npmjs 為前提**(傳播延遲量級、探針用 `--registry=https://registry.npmjs.org/`);依約 CLAUDE.md 不由本輪修改,待主控更新.
